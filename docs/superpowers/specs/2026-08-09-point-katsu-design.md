# ポイ活ランチャー Design

## 目的
夫婦それぞれがiPhoneから1タップで、その日に実施すべきポイ活サービスへ移動できる軽量PWAを作る。

## 基本方針
- GitHub Pagesで配信できる静的HTML/CSS/JavaScriptのみで構成する。
- ログインID、パスワード、Cookie、PayPay等の認証情報は保存しない。
- 外部サービスへのログインや「くじを引く」等の操作は自動化せず、対象ページを開くところまでに留める。
- 実施済み状態は各iPhoneのlocalStorageに保存し、夫婦間では同期しない。
- 日次・週次・月次・一度だけの頻度を各サービスに設定できる。
- サービス追加・URL変更は設定データの編集だけで行える。

## UI
- 今日やる項目を上部に表示する。
- 各項目はサービス名、頻度、状態、開くボタンを持つ。
- 開く操作時に実施済みにできる。誤操作用に実施済み解除も可能にする。
- 今日対象外の項目は別セクションに折りたたむ。
- 「残りN件」を表示する。
- iPhoneのホーム画面追加を想定したレスポンシブUIとする。

## データモデル
各サービスは `id`, `name`, `url`, `frequency`, `enabled` を持つ。
`frequency` は `daily`, `weekly`, `monthly`, `once` の4種類。
週次は曜日、月次は日付を追加属性で指定できる。

## 状態管理
localStorageにサービスごとの最終実施日を保存する。対象判定は端末のローカル日付で行う。週次・月次は該当日だけ今日の対象とする。一度だけは完了後に対象外になる。

## 配布
GitHubリポジトリで管理し、GitHub Pagesから配信できる構成にする。PWA用manifestとservice workerを含め、ホーム画面から起動できるようにする。

## 非対象
- 外部サービスへの自動ログイン
- くじ・広告・チェックイン等の自動クリック
- 夫婦間の完了状態同期
- サーバー、DB、アカウント機能
